# Contributing to PlotStatLab

PlotStatLab (PSL) welcomes improvements to usability, charts, statistics, documentation and distribution. Code is provided under the [MIT license](LICENSE). Repository visibility and GitHub permissions still control who can access and propose changes.

## Before changing code

Read the [expert guide](docs/EXPERT-GUIDE.md) and [roadmap](docs/ROADMAP.md). For a bug, include version, OS, minimal reproduction, actual/expected behavior and error text. Use synthetic examples instead of private research or personal data.

For a substantial feature, explain the problem and intended behavior before implementing it. Statistical features need a supported-design specification, assumptions, treatment of pairing/missing values, correction method and independent validation references.

## Development setup

End users run the launcher with the compiled interface. Interface contributors need Node.js compatible with Vite 7, pnpm compatible with the repository configuration and Python 3.12.

```sh
pnpm install
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
pnpm build
```

On Windows, use `.venv\Scripts\python.exe` instead of `.venv/bin/python`.

For development, run the API and Vite in separate terminals:

```sh
.venv/bin/python -m uvicorn server.app:app --host 127.0.0.1 --port 8765
pnpm dev
```

The interface uses `http://127.0.0.1:5173`; the local API uses port 8765. Development and production browser storage are separate origins.

## Validation

```sh
pnpm build
pnpm test
.venv/bin/python -m pytest tests -q
```

For browser tests, build the interface, start the production server on port 8765, then run:

```sh
pnpm exec playwright install chromium
pnpm test:e2e
```

If the environment prevents the browser from starting, record the blocker; do not report that suite as passing. Cross-platform setup and distribution checks are defined under `.github/workflows/`.

### Chart/export review criteria

- Coordinates and summaries reflect the underlying measurements.
- Missing, negative, logarithmic and empty-group cases have explicit behavior.
- Formatting does not change statistical values.
- Observation IDs stay stable for the same observation.
- Style transfer preserves destination point overrides.
- Stale results do not generate significance annotations.
- SVG preserves editable text/vector objects without external CSS or editor controls.
- Saving and reopening a `.psl` or legacy `.labplot` preserves supported properties.

### Statistical review criteria

Use independent numerical references or published examples, not only tests that mirror the implementation. Check design, subject-ID alignment, adjusted p-values, intervals, degenerate cases and compatibility messages. Name both the omnibus test and pairwise method accurately. Outlier flags and exclusions must preserve original measurements and make analytical effects explicit.

## Submit a change

Use a branch and focused commits. In the pull request, explain the problem, final behavior, validation and material limits. Include a screenshot for interface changes. Update guides and changelog when user behavior changes.

Do not commit `.venv`, caches, credentials, private measurements or temporary files. Distribution packages should be generated by the release process and include only intended artifacts. Keep a development/private release distinct from a public announcement; publication is a deliberate maintainer action.
